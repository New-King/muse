# Muse 开发计划

## 一句话

一个能演示、也能被追问三层的 AI 设计画布。做完之后，每一行代码都能解释为什么。

---

## 范围

**做：**

- 邮箱密码登录（Supabase Auth），单用户工作区
- 项目列表：新建、重命名、删除
- 画布：Excalidraw 集成，自动保存
- 对话：流式输出、历史持久化、断线重连
- Agent：工具调用（生成图像、读画布、写画布）
- 图像生成：异步任务 + 队列 + 重试

**不做：**

- 支付、订阅、积分
- Skills 市场、品牌套件
- 视频生成
- 团队协作、多租户

砍掉的理由：这些是产品功能，不是工程能力。少做一半，才能把剩下的一半讲透。

---

## 里程碑

每一步的顺序是「先能跑，再能讲」。做完一个里程碑，写一段 200 字以内的说明：解决了什么、怎么做的、哪里还可能出问题。

### M0 · 骨架（0.5 天）

- pnpm workspace、Turborepo、共享 tsconfig、Biome
- `apps/web` 起一个空白页，`apps/server` 起一个 `/health`
- 一条命令 `pnpm dev` 同时起两个进程

**要讲清楚：** 为什么 monorepo；`packages/shared` 放什么（类型、协议、常量）。

### M1 · 认证与项目（1 天）

- Supabase Auth 登录/注册/登出，会话保持
- `projects` 表 + RLS：每个用户只能看到自己的
- 项目列表页：空状态、新建、重命名、删除

**要讲清楚：** 为什么把鉴权放数据库（RLS）而不是只在服务端判断；客户端拿到 anon key 为什么安全。

### M2 · 画布（1–2 天）

- 集成 Excalidraw，加载/保存 `canvas` JSON
- 自动保存：防抖、并发写、失败重试
- 视口、缩放、快捷键

**要讲清楚：** 保存策略为什么用防抖 + 版本号；两个人同时改怎么处理（本项目单用户，但要说明取舍）。

### M3 · 对话与流式（2 天）

- WebSocket 协议设计：`agent.run`、`token`、`tool.start`、`tool.end`、`run.completed`、`run.failed`
- 消息落库：用户消息先写，助手消息整轮结束写
- 断线重连与事件补发
- 前端消息列表：流式渲染、工具卡片、错误态

**要讲清楚：** 为什么选 WS 不用 SSE；重连后如何补齐丢失的事件；消息顺序如何保证。

### M4 · Agent 运行时（2–3 天）

- 自建 ReAct loop：模型输出 → 工具调用 → 结果回灌 → 直到纯文本
- 工具：`generate_image`、`inspect_canvas`、`manipulate_canvas`
- 多轮记忆：消息链持久化
- 中止：用户点停止，如何取消进行中的 run

**要讲清楚：** 不依赖 LangGraph 自己写 loop 的边界在哪；工具调用失败怎么反馈给模型；如何防止模型乱改画布。

### M5 · 异步图像生成（1–2 天）

- 任务表 + 队列 + Worker
- 幂等键、重试、超时、失败原因
- 生成完成后写回画布、通知前端

**要讲清楚：** 为什么不用同步请求；队列重复消费怎么防；用户关掉页面后任务还要不要继续。

### M6 · 打磨（1–2 天）

- 空状态、加载骨架、错误提示
- 键盘操作、响应式
- 首屏性能、图片懒加载

**要讲清楚：** 性能瓶颈在哪、怎么测的。

---

## 每步的产出

1. 能跑的代码
2. `docs/notes/Mx.md`：200 字以内的「做了什么 / 为什么 / 已知问题」
3. 一段 30 秒的口头说明，能对着这三点讲

## 原则

- 不复制别人的实现。卡住时看参考项目，是为了理解思路，不是为了拿代码。
- 先写最小可用版本，再重构。不要一上来就抽象。
- 每个抽象都要有第二个使用者才提炼。

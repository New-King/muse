# M1 · 分层与项目数据

## 做了什么

- 服务端拆成三层：`http/`（路由，只做校验和响应）→ `features/`（业务：service + repository）→ `db/`（Supabase 客户端）
- 数据模型定稿：`projects` → `canvases` / `sessions` → `messages`，会话挂在 project 上而不是 canvas 上
- 迁移文件 `supabase/migrations/0001_init.sql`：四张表 + 索引 + RLS 策略 + `updated_at` 触发器
- `GET/POST/PATCH/DELETE /projects` 四个接口，含名称校验（1–60 字）
- 前端左栏改成读真实数据：RSC 里取 `/projects`，「新建项目」按钮 POST 后 `router.refresh()`

## 为什么

repository 抽成接口，是因为现在没有可用的数据库：Supabase 实现和内存实现各写一份，`PROJECTS_STORE` 决定用哪个。换成真库时只改环境变量，不动业务代码。

## 已知问题

- 登录还没接，所有请求都归到 `DEV_USER_ID` 这个占位用户；RLS 策略写好了但暂时没生效（走的是 service_role）
- 原 Supabase 项目处于 INACTIVE（被暂停），已触发恢复，恢复完成前走内存模式，重启数据即丢
- 画布和对话还是静态占位，没有接 `canvases` / `sessions` 表
